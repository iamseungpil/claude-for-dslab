# 한국어 학술 글쓰기 원칙

연세대 글쓰기 합평 스터디(승필 진행) 자료에서 추출한 4층 원칙. paper-section-rewrite와 academic-writing-trainer가 공유.

---

## 4대 평가축 (Notion 1·2주차)

학술 글의 모든 점검은 다음 4축으로 환원된다.

| 축 | 점검 질문 |
|---|---|
| **주제(의도)** | 명확한가 / 적절한가 / 참신한가 / 예상 독자를 고려했는가 / 글의 목표가 제시되었는가 |
| **내용** | 풍부한가 / 구체적인가 / 통일성 있는가 |
| **구성(구조)** | 단락이 짜임새 있게 배열되었는가 / 간결하게 구조화되었는가 / 핵심을 간추릴 수 있는가 / 문장과 문장의 연결이 논리적인가 |
| **표현(문장)** | 한 문장에 하나의 논리인가 / 주어-서술어가 명확한가 / 빼야 할 수식어는 없는가 / 생략 가능한 어구는 없는가 |

각 축은 채점 시 1-3점 척도로 평가된다. 상세 rubric은 [scoring-rubrics.md](scoring-rubrics.md).

## 글쓰기 3과정 (Notion 1주차)

| 단계 | 내용 |
|---|---|
| **계획** | 글의 목표·논리 구조·단락 구성·서술 방식을 먼저 결정. 자료 수집 + 브레인스토밍. |
| **수행** | 계획한 목표·논리·단락·서술을 바탕으로 적확한 어휘·문장 작성. |
| **평가** | 완성된 글의 장단점 분석. 자가/동료/교수 피드백. 한 문장·문단을 바꾸어도 전체 구성을 고려. |

## 9가지 서술 방식 (Notion 1주차) — 문장 단위 카테고리

**각 문장은 다음 9가지 중 한 카테고리를 가진다.** Coach는 매 문단 critic에서 사용자 문장 각각에 카테고리 라벨을 붙이고, 그 흐름이 단락 역할에 적합한지 점검한다.

| # | 방식 | 역할 | 시그널 표현 |
|---|---|---|---|
| 1 | **정의** | 피정의항(종개념) + 정의항(종차+유개념). 새 용어 도입 시 | "X는 Y이다" / "X란 ..." |
| 2 | **분류/구분** | 공통 특성 기준으로 묶거나 나눔. 상호 배타적 | "X는 A, B, C로 나뉜다" |
| 3 | **분석** | 복잡한 대상을 구성요소로 분해 | "X는 ~, ~, ~로 구성된다" |
| 4 | **비교/대조** | 같은 범주 내 공통점/차이점. 기존 방법 대비 차별성 | "X와 달리 / X에 비해 / X와 같이" |
| 5 | **예시** | 구체적 예. 추상 → 구체 | "예를 들어 / 가령 / 구체적으로" |
| 6 | **인용** | 타인의 말·글로 자기 주장 뒷받침 | "[N]에 따르면 / Y는 ~라고 하였다" |
| 7 | **유추** | 다른 범주의 친숙한 것에서 비유 | "X는 마치 Y와 같다" |
| 8 | **과정** | "어떻게"에 답하는 단계 서술 | "먼저 ~한 뒤 / ~하고 나면" |
| 9 | **인과** | "왜"에 답하는 원인-결과 | "그러므로 / 따라서 / 때문에 / 이는 ~을 의미한다" |

## 단락 역할별 권장 서술 방식 흐름 ★ 문장 단위 critic의 핵심

**연구 제안서 5문단**의 단락마다 권장 sentence flow. Coach는 사용자 문장의 카테고리 시퀀스가 이 흐름과 얼마나 맞는지 점검한다.

| 단락 역할 | 권장 흐름 | 의무 카테고리 | 회피 |
|---|---|---|---|
| **1. 배경** | 정의 → 인과(왜 중요) → 예시(현황) | 정의, 인과 | 비교/대조 (아직 본 연구 X 등장) |
| **2. 한계** | 비교/대조(기존 vs 이상) → 분석(한계의 구성) → 인과(그래서 막힘) | 분석, 인과 | 정의 일변도 |
| **3. 제안** | 정의(무엇을) → 분석(구성요소) → 과정(어떻게 작동) | 정의, 분석 | 인과만 (왜만 있고 무엇 모호) |
| **4. 차별성** | 비교/대조(기존 vs 본 연구) → 인과(왜 다른 게 의미) | 비교/대조 | 단순 정의 (뭐가 다른지 안 보임) |
| **5. 평가** | 정의(벤치마크) → 과정(평가 방법) → 인과(예상 결과·기여) | 과정, 인과 | 비교 (벤치마크 비교는 별 단락) |

### 사용 예 — Coach 출력

문단 3(제안) 사용자 작성 prose:
> "본 연구는 사용자 궤적과 프로그램 합성을 결합한 프레임워크를 제안한다. (S1) 이 프레임워크는 뉴로-심볼릭 모듈, 프로그램 실행 모듈, 프로그램 평가 모듈로 구성된다. (S2) 예를 들어, ARC 문제를 풀 때 평가 모듈이 사람 궤적과 비교해 사전 지식을 갱신한다. (S3) 이러한 구조는 학습하지 않은 작업까지 해결할 수 있게 한다. (S4)"

Coach 카테고리 라벨링:
```
S1 [정의]    ✓ lead로 적절 (제안 단락의 1번)
S2 [분석]    ✓ 정의 → 분석 자연스러움
S3 [예시]    ✓ 분석 다음 예시 자연스러움
S4 [인과]    ⚠ 권장 흐름은 정의→분석→과정. 인과는 "차별성" 단락 영역
            → 마지막 문장을 [과정] (어떻게 작동하는지 시퀀스)으로 바꾸면 더 적합
```

### 사용 예 — 실패 케이스

문단 2(한계) 사용자 작성:
> "기존 LLM은 다양한 데이터를 학습한 모델이다. 생성 모델은 분포를 모사하는 모델이다. 두 모델 모두 패턴 인식 능력을 가진다."

Coach 카테고리 라벨링:
```
S1 [정의]    ⚠ 한계 단락 lead로 부족. 비교/대조 권장
S2 [정의]    ⚠ 정의가 또 나옴 (R4 인접 중복 위험)
S3 [정의]    ✗ 한계 단락에 정의만 3개 — 이 단락의 의무 카테고리(분석, 인과)가 0개

흐름: 정의 → 정의 → 정의
역할 정합도: 1/5 (한계 단락의 의무 카테고리 [분석, 인과] 모두 누락)

권장: "한계" 단락은 이런 흐름이 자연스러워요.
   비교/대조 (기존 모델 vs 본 연구가 원하는 능력) → 분석 (한계의 구체적 원인 분해)
   → 인과 (왜 이게 본 연구의 동기가 되는지)

예: "기존 LLM·생성 모델은 일반화에 강하지만 새로운 작업에 대한 적응력이 부족하다.
[비교/대조] 이는 학습 분포 밖 입력에 대한 메커니즘이 명시적이지 않기 때문이다. [분석]
따라서 학습하지 않은 규칙의 작업을 풀려면 새로운 접근이 필요하다. [인과]"
```

이 흐름 라벨링이 **체화의 핵심 도구**다. 같은 카테고리 흐름을 5문단에 걸쳐 반복 적용하면, 사용자가 다음 글에서는 자기 검열로 이 카테고리들을 의식하게 된다.

## 논증의 구성 (Notion 1주차)

**주장(명제) + 논거 + 추론**.

### 명제 종류
- **사실 명제**: 진위 판단 ("한글은 과학적 문자이다")
- **가치 명제**: 가치 판단 ("인간은 존엄하다")
- **정책 명제**: 의견·주장 ("학생은 학칙을 지켜야 한다")

연구 제안서의 thesis는 보통 **정책 명제**(제안하는 방법론)이거나 **사실 명제**(보이려는 결과).

### 논거 종류
- **사실 논거**: 직접 목격, 실험 결과, 보편화된 사실, 역사적 공인 사실. 강함.
- **소견 논거**: 타인의 경험·증언, 전문가 의견. 보조적.

연구 제안서는 사실 논거 우세, 소견 논거는 도입부 동기 부분에서만.

### 추론 4종
- **연역**: 일반 원리 → 특수 사실 (대전제·소전제·결론)
- **귀납(일반화)**: 특수 사례 → 일반 원리
- **유비**: 두 대상의 일부 속성 동일 → 다른 속성도 동일 추정
- **변증법**: 주장 + 반론 → 종합 (limitation 설명에 자주 쓰임)

## 문단의 3원칙 (Notion 3주차)

| 원칙 | 설명 |
|---|---|
| **통일성(unity)** | 주제/소주제와 뒷받침 문장의 내용적 일치. 한 문단은 한 생각. |
| **연결성(coherence)** | 뒷받침 문장들이 순리적으로 배열. 문단 바깥 내용 끌어오지 않음. 접속어 ("그러나/예를 들어/따라서") 적절. |
| **완결성(completeness)** | 소주제문 + 충분한 뒷받침 문장. 너무 짧으면 fail. |

**위반 예시**: 단락이 길고 두서없이 흐르다 마지막에 갑자기 새 주장 등장 → 통일성 위반.

## 문단의 5유형 (Notion 3주차)

| 유형 | 구조 | 권장 사용 |
|---|---|---|
| **두괄식** | 소주제문 + 뒷받침 | **학술 글 디폴트.** 가장 일반적·무난. 첫 문장 = thesis. |
| **미괄식** | 뒷받침 + 소주제문 | 흥미를 끌어가야 할 때 (학술에선 도입 일부에만) |
| **쌍괄식** | 소주제문 + 뒷받침 + 소주제문 재진술 | 강조 필요 시 |
| **중괄식** | 뒷받침 + 소주제문 + 뒷받침 | 핵심 묻혀 비권장 |
| **무괄식** | 뒷받침만, 소주제문 잠재 | 예시 단락에만 |

학술 글은 **두괄식 디폴트**. 모든 단락의 첫 문장이 그 단락의 thesis여야 한다.

## 문장의 6원칙 (Notion 3주차)

1. **문법에 맞아야 한다** — 기본
2. **하나의 문장은 하나의 생각** — 무엇이 어찌하다 / 무엇이 어떠하다 / 무엇이 무엇이다
3. **주어-서술어 일치** — 한 문장에 주술 2개 이상 X. 안긴문장 깊이 ≤ 2
4. **피동/능동 구분** — 불필요한 피동(`-됩니다`, `-되어진다`) 회피
5. **`-적/-의/것/수/있다` 회피** — 명사형 누적 금지. 풀어쓰기
6. **연결 어미 주의** — 특히 `-데`(가급적 사용 X), `-에 의해`, `-에 대한` (번역투)

상세 패턴은 [banned-phrases-ko.md](banned-phrases-ko.md).

## 퇴고 시 점검 사항 (Notion 4주차)

각 글을 다 쓴 뒤 4단계로 점검.

### 1. 주제 점검
- 예상 독자를 고려했는가
- 글의 목표가 제시되었는가

### 2. 구조 점검
- 문서가 하나의 주제로 작성되어 있는가
- 보고서 작성 목적·목표가 뚜렷한가
- 결론을 쉽게 이해하고 읽을 수 있게 작성했는가

### 3. 단락 점검
- 하나의 논제·주제를 사용하고 있는가
- 주제를 바르게 전달하도록 단락 배열되었는가
- 단락의 논리를 파악하기 쉬운가

### 4. 표현 점검
- 한 문장에 하나의 논리인가
- 논제를 바르게 전달하는 문장 배열인가
- 문장의 주어와 서술어가 명확한가
- 빼야 할 수식어는 없는가
- 생략해도 좋을 문장·어구는 없는가

## 금지 표현 (학술 글 일반)

paper-digest와 humanize 스킬에서 누적된 학술 회피 표현:

- "we now turn to" / "이제 ~로 넘어간다"
- "in summary" / "요약하면" (서두 X)
- "it is worth noting" / "특기할 만한 점은"
- "additionally" / "moreover" / "또한" 남용
- "first attempt to our knowledge" (overclaim)

상세는 [banned-phrases-ko.md](banned-phrases-ko.md), [banned-phrases-en.md](banned-phrases-en.md).
