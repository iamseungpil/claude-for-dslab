# 한국어 학술 글쓰기 원칙

연세대 글쓰기 합평 스터디(승필 진행) 자료에서 추출한 4층 원칙. paper-section-rewrite와 academic-writing-trainer가 공유.

---

## 4대 평가축 (Notion 1·2주차)

학술 글의 모든 점검은 다음 4축으로 환원된다.

| 축 | 점검 질문 |
|---|---|
| **주제(의도)** | 명확한가 / 적절한가 / 참신한가 / 예상 독자를 고려했는가 / 글의 목표가 제시되었는가 |
| **내용** | 풍부한가 / 구체적인가 / 통일성 있는가 |
| **구성(구조)** | 단락이 짜임새 있게 배열되었는가 / 간결하게 구조화되었는가 / 핵심을 간추릴 수 있는가 / 문장과 문장의 연결이 논리적인가 |
| **표현(문장)** | 한 문장에 하나의 논리인가 / 주어-서술어가 명확한가 / 빼야 할 수식어는 없는가 / 생략 가능한 어구는 없는가 |

각 축은 채점 시 1-3점 척도로 평가된다. 상세 rubric은 [scoring-rubrics.md](scoring-rubrics.md).

## 글쓰기 3과정 (Notion 1주차)

| 단계 | 내용 |
|---|---|
| **계획** | 글의 목표·논리 구조·단락 구성·서술 방식을 먼저 결정. 자료 수집 + 브레인스토밍. |
| **수행** | 계획한 목표·논리·단락·서술을 바탕으로 적확한 어휘·문장 작성. |
| **평가** | 완성된 글의 장단점 분석. 자가/동료/교수 피드백. 한 문장·문단을 바꾸어도 전체 구성을 고려. |

## 9가지 서술 방식 (Notion 1주차) — 문장 단위 카테고리

**각 문장은 다음 9가지 중 한 카테고리를 가진다.** Coach는 매 문단 critic에서 사용자 문장 각각에 카테고리 라벨을 붙이고, 그 흐름이 단락 역할에 적합한지 점검한다.

| # | 방식 | 역할 | 시그널 표현 |
|---|---|---|---|
| 1 | **정의** | 피정의항(종개념) + 정의항(종차+유개념). 새 용어 도입 시 | "X는 Y이다" / "X란 ..." |
| 2 | **분류/구분** | 공통 특성 기준으로 묶거나 나눔. 상호 배타적 | "X는 A, B, C로 나뉜다" |
| 3 | **분석** | 복잡한 대상을 구성요소로 분해 | "X는 ~, ~, ~로 구성된다" |
| 4 | **비교/대조** | 같은 범주 내 공통점/차이점. 기존 방법 대비 차별성 | "X와 달리 / X에 비해 / X와 같이" |
| 5 | **예시** | 구체적 예. 추상 → 구체 | "예를 들어 / 가령 / 구체적으로" |
| 6 | **인용** | 타인의 말·글로 자기 주장 뒷받침 | "[N]에 따르면 / Y는 ~라고 하였다" |
| 7 | **유추** | 다른 범주의 친숙한 것에서 비유 | "X는 마치 Y와 같다" |
| 8 | **과정** | "어떻게"에 답하는 단계 서술 | "먼저 ~한 뒤 / ~하고 나면" |
| 9 | **인과** | "왜"에 답하는 원인-결과 | "그러므로 / 따라서 / 때문에 / 이는 ~을 의미한다" |

## 단락 역할별 권장 서술 방식 흐름 ★ 문장 단위 critic의 핵심

**연구 제안서 5문단**의 단락마다 권장 sentence flow. Coach는 사용자 문장의 카테고리 시퀀스가 이 흐름과 얼마나 맞는지 점검한다.

| 단락 역할 | 권장 흐름 | 의무 카테고리 | 회피 |
|---|---|---|---|
| **1. 배경** | 정의 → 인과(왜 중요) → 예시(현황) | 정의, 인과 | 비교/대조 (아직 본 연구 X 등장) |
| **2. 한계** | 비교/대조(기존 vs 이상) → 분석(한계의 구성) → 인과(그래서 막힘) | 분석, 인과 | 정의 일변도 |
| **3. 제안** | 정의(무엇을) → 분석(구성요소) → 과정(어떻게 작동) | 정의, 분석 | 인과만 (왜만 있고 무엇 모호) |
| **4. 차별성** | 비교/대조(기존 vs 본 연구) → 인과(왜 다른 게 의미) | 비교/대조 | 단순 정의 (뭐가 다른지 안 보임) |
| **5. 평가** | 정의(벤치마크) → 과정(평가 방법) → 인과(예상 결과·기여) | 과정, 인과 | 비교 (벤치마크 비교는 별 단락) |

### 사용 예 — Coach 출력

문단 3(제안) 사용자 작성 prose:
> "본 연구는 사용자 궤적과 프로그램 합성을 결합한 프레임워크를 제안한다. (S1) 이 프레임워크는 뉴로-심볼릭 모듈, 프로그램 실행 모듈, 프로그램 평가 모듈로 구성된다. (S2) 예를 들어, ARC 문제를 풀 때 평가 모듈이 사람 궤적과 비교해 사전 지식을 갱신한다. (S3) 이러한 구조는 학습하지 않은 작업까지 해결할 수 있게 한다. (S4)"

Coach 카테고리 라벨링:
```
S1 [정의]    ✓ lead로 적절 (제안 단락의 1번)
S2 [분석]    ✓ 정의 → 분석 자연스러움
S3 [예시]    ✓ 분석 다음 예시 자연스러움
S4 [인과]    ⚠ 권장 흐름은 정의→분석→과정. 인과는 "차별성" 단락 영역
            → 마지막 문장을 [과정] (어떻게 작동하는지 시퀀스)으로 바꾸면 더 적합
```

### 사용 예 — 실패 케이스

문단 2(한계) 사용자 작성:
> "기존 LLM은 다양한 데이터를 학습한 모델이다. 생성 모델은 분포를 모사하는 모델이다. 두 모델 모두 패턴 인식 능력을 가진다."

Coach 카테고리 라벨링:
```
S1 [정의]    ⚠ 한계 단락 lead로 부족. 비교/대조 권장
S2 [정의]    ⚠ 정의가 또 나옴 (R4 인접 중복 위험)
S3 [정의]    ✗ 한계 단락에 정의만 3개 — 이 단락의 의무 카테고리(분석, 인과)가 0개

흐름: 정의 → 정의 → 정의
역할 정합도: 1/5 (한계 단락의 의무 카테고리 [분석, 인과] 모두 누락)

권장: "한계" 단락은 이런 흐름이 자연스러워요.
   비교/대조 (기존 모델 vs 본 연구가 원하는 능력) → 분석 (한계의 구체적 원인 분해)
   → 인과 (왜 이게 본 연구의 동기가 되는지)

예: "기존 LLM·생성 모델은 일반화에 강하지만 새로운 작업에 대한 적응력이 부족하다.
[비교/대조] 이는 학습 분포 밖 입력에 대한 메커니즘이 명시적이지 않기 때문이다. [분석]
따라서 학습하지 않은 규칙의 작업을 풀려면 새로운 접근이 필요하다. [인과]"
```

이 흐름 라벨링이 **체화의 핵심 도구**다. 같은 카테고리 흐름을 5문단에 걸쳐 반복 적용하면, 사용자가 다음 글에서는 자기 검열로 이 카테고리들을 의식하게 된다.

## 논증의 구성 (Notion 1주차)

**주장(명제) + 논거 + 추론**.

### 명제 종류
- **사실 명제**: 진위 판단 ("한글은 과학적 문자이다")
- **가치 명제**: 가치 판단 ("인간은 존엄하다")
- **정책 명제**: 의견·주장 ("학생은 학칙을 지켜야 한다")

연구 제안서의 thesis는 보통 **정책 명제**(제안하는 방법론)이거나 **사실 명제**(보이려는 결과).

### 논거 종류
- **사실 논거**: 직접 목격, 실험 결과, 보편화된 사실, 역사적 공인 사실. 강함.
- **소견 논거**: 타인의 경험·증언, 전문가 의견. 보조적.

연구 제안서는 사실 논거 우세, 소견 논거는 도입부 동기 부분에서만.

### 추론 4종
- **연역**: 일반 원리 → 특수 사실 (대전제·소전제·결론)
- **귀납(일반화)**: 특수 사례 → 일반 원리
- **유비**: 두 대상의 일부 속성 동일 → 다른 속성도 동일 추정
- **변증법**: 주장 + 반론 → 종합 (limitation 설명에 자주 쓰임)

## 문단의 3원칙 (Notion 3주차)

| 원칙 | 설명 |
|---|---|
| **통일성(unity)** | 주제/소주제와 뒷받침 문장의 내용적 일치. 한 문단은 한 생각. |
| **연결성(coherence)** | 뒷받침 문장들이 순리적으로 배열. 문단 바깥 내용 끌어오지 않음. 접속어 ("그러나/예를 들어/따라서") 적절. |
| **완결성(completeness)** | 소주제문 + 충분한 뒷받침 문장. 너무 짧으면 fail. |

**위반 예시**: 단락이 길고 두서없이 흐르다 마지막에 갑자기 새 주장 등장 → 통일성 위반.

## 문단의 5유형 (Notion 3주차)

| 유형 | 구조 | 권장 사용 |
|---|---|---|
| **두괄식** | 소주제문 + 뒷받침 | **학술 글 디폴트.** 가장 일반적·무난. 첫 문장 = thesis. |
| **미괄식** | 뒷받침 + 소주제문 | 흥미를 끌어가야 할 때 (학술에선 도입 일부에만) |
| **쌍괄식** | 소주제문 + 뒷받침 + 소주제문 재진술 | 강조 필요 시 |
| **중괄식** | 뒷받침 + 소주제문 + 뒷받침 | 핵심 묻혀 비권장 |
| **무괄식** | 뒷받침만, 소주제문 잠재 | 예시 단락에만 |

학술 글은 **두괄식 디폴트**. 모든 단락의 첫 문장이 그 단락의 thesis여야 한다.

## 문장의 6원칙 (Notion 3주차)

1. **문법에 맞아야 한다** — 기본
2. **하나의 문장은 하나의 생각** — 무엇이 어찌하다 / 무엇이 어떠하다 / 무엇이 무엇이다
3. **주어-서술어 일치** — 한 문장에 주술 2개 이상 X. 안긴문장 깊이 ≤ 2
4. **피동/능동 구분** — 불필요한 피동(`-됩니다`, `-되어진다`) 회피
5. **`-적/-의/것/수/있다` 회피** — 명사형 누적 금지. 풀어쓰기
6. **연결 어미 주의** — 특히 `-데`(가급적 사용 X), `-에 의해`, `-에 대한` (번역투)

상세 패턴은 [banned-phrases-ko.md](banned-phrases-ko.md).

## Insight-first 원칙 ★ (paper-digest 통합)

**"무엇을 한다"가 아니라 "왜 새롭다"가 첫 문장에 와야 한다.** 학술 글의 lead 문장은 단순 사실 나열로 시작하면 독자가 메시지를 못 잡는다. paper-digest의 핵심 원칙이며, paper-section-rewrite Level 1·2의 게이트로 작동한다.

### 판정 기준

| 기준 | ✗ 단순 나열 | ✓ Insight-first |
|---|---|---|
| 의도 1문장 | "본 연구는 모듈 A·B·C를 제안한다" | "본 연구는 OOD 일반화 격차를 사전 지식 갱신으로 메우는 프레임워크를 제안한다" |
| 단락 lead | "본 모델은 3개 모듈로 구성된다" | "본 모델은 사전 지식 갱신으로 OOD 격차를 메운다" |
| 결과 단락 lead | "정확도가 78%였다" | "본 방법은 baseline 대비 +12%p로 OOD 격차를 절반으로 줄였다" |

판정 절차: lead 문장에서 **WHY가 보이는가** — 새로움·기여·메커니즘 중 하나가 명시돼 있어야 한다. WHAT만 있으면 ✗ → "왜" 한 절을 합쳐 재작성.

## 자연스러움 원칙 ★ (humanize 통합)

**em-dash 0**은 정량 게이트, 자연스러움은 다음 패턴들의 누적으로 본다. 단락당 누적 ≥ 3 = ✗.

### 검출 패턴 (KO)

| 패턴 | 시그널 | 자연 대안 |
|---|---|---|
| 번역투 대조구문 | "~에 대한 / ~에 의해 / ~을 통해" | "~의 / ~이 / 직접 단정문" |
| 메타인지 표현 남발 | "~라고 할 수 있다 / ~라고 볼 수 있다 / ~로 사료된다" | 단정문으로 (확신 없을 때만 한정사 1개) |
| 격식체 과다 | "~함으로써 / ~에 있어 / ~에 다름 아니다" | "~해 / ~에서 / ~이다" |
| 명사형 누적 | "~의 ~의 ~의" / "분석을 통한 모색" | 동사형으로 풀어쓰기 |
| 기계적 병렬 | "첫째 ~ 둘째 ~ 셋째" 의도 없는 나열 | 자연스러운 접속어로 흐름 |
| Em-dash 남발 | `—` 사용 ≥ 1 | 쉼표·괄호·마침표·접속어로 분리 |

### 검출 패턴 (EN)

| 패턴 | 시그널 | 자연 대안 |
|---|---|---|
| 격식 부정 | "with respect to / by means of / through which / vis-à-vis / inasmuch as" | "for / by / in / about" 같은 단순 전치사 |
| 메타인지 | "it is worth noting / it can be argued / one might consider" | 직접 단정문 |
| 무의미 강조 | "clearly / obviously / various / numerous" | 빈도 양화 (특정 수치) |
| 접속 부풀림 | "moreover / furthermore / additionally" 단락당 ≥ 2 | 한 번만, 또는 자연 접속 |
| Em-dash 남발 | `—` ≥ 1 | comma / parenthesis |

핵심 — **"한 패턴이 있다"가 ✗가 아니다.** 누적 ≥ 3이면 글에 AI 톤이 베인 것이고, 이 때 자연스러움 게이트가 fail.

## 논리적 비약 원칙 ★ (iterative-academic-writing 통합)

**인접 문장 사이 추론이 한 단계씩 명시적이어야** 한다. 비약은 학술 글의 신뢰성을 직접 깎는다.

### 4가지 비약 패턴

| 패턴 | 모습 | 보완 |
|---|---|---|
| **결론 비약** | "loss가 떨어졌다. 따라서 일반화가 향상됐다." | 중간 단계 한 문장: "이 loss는 OOD held-out에서 측정됐다. 따라서 ..." |
| **암묵적 가정** | "cosine similarity가 0.8을 넘어 의미 있는 클러스터링이다." | "0.8은 본 데이터셋에서 무작위 짝의 95% 이상이다. 따라서 ..." |
| **수치 → 결론 비약** | "정확도가 78%이다. 본 방법이 우월하다." | baseline 비교·통계 유의성·신뢰구간 한 문장 추가 |
| **시점·시제 혼동** | "기존 방법은 X를 못 한다 (현재). 본 방법은 X를 했다 (과거 결과)." | 시제 통일 또는 비교 시점 명시 |

판정: 단락당 비약 **≥ 1** = ✗. 중간 단계 한 문장 추가하거나 한정 표현으로 약화.

## ML-beginner 가독성 원칙 ★ (humanize + 가독성)

각 단락 첫 문장이 ML 비전공자에게 이해 가능한지 점검한다. 본 스킬은 도메인 외 독자가 lead만 따라가도 글의 줄기를 잡을 수 있어야 한다.

### 3개 게이트

1. **약어 first-use 풀어쓰기** — 단락에 처음 등장하는 약어가 풀어쓰기 없이 등장하면 ✗
   - 예: 첫 등장이 "RLHF는 ..." → ✗ → "사람 피드백 강화 학습(RLHF)은 ..." 또는 "RLHF (사람 피드백 강화 학습)는 ..."
2. **수식 도입 전 자연어 설명** — 수식이 자연어 설명 없이 갑자기 등장 → ✗
   - 예: 갑자기 `\theta = \arg\min_\theta \mathbb{E}_x [\ell(f_\theta(x))]` → ✗ → "본 모델은 평균 손실을 최소화하는 파라미터를 학습한다. 즉, $\theta = \arg\min ...$" 순서
3. **고밀도 jargon** — 한 문장에 ML jargon 4개 이상 (예: transformer + attention + KV-cache + FlashAttention) → ✗ → 두 문장 이상으로 분리

### 한국어 학술 register 환산표

영어 jargon이 첫 등장 시 inline gloss를 붙인다.

| EN | KO 권장 풀어쓰기 |
|---|---|
| behavior layer | 행동 층 |
| factorial benchmark | 요인 설계 벤치마크 |
| instruction-following | 지시 따르기 |
| chain-of-thought | 사고 사슬 |
| instrumental sub-goal | 다른 목표를 이루기 위한 부분 목표 |

예: "도구적 부분 목표(다른 목표를 위해 자기 작동을 유지하려는 구조)".

## 자기 완결성 원칙 ★

학술 글의 섹션·단락은 **다른 섹션을 인용하지 않고도 읽힐 수 있어야** 한다. 본 스킬 Phase 5의 게이트가 이 원칙으로 작동한다.

### 검출 패턴

| 패턴 | KO | EN |
|---|---|---|
| 섹션 참조 | `Section [0-9]`, `§[0-9]`, `[0-9]장`, `위에서 다룬`, `앞서 언급한` | `Section [0-9]+`, `§[0-9]+`, `as discussed in`, `aforementioned` |
| 부록 참조 | `부록 [A-Z]`, `appendix` | `Appendix [A-Z]`, `App. [A-Z]` |
| Forward reference | `다음 섹션에서` | `in the next section`, `we will show` |

### 처리 규칙

1. 본문에 핵심 정의·식이 흩어져 있으면 → 본 섹션에 자기 완결적 **1줄 요약**을 패러프레이징해 삽입 (반복 X)
2. 부록 의존이 클 경우 → 부록 핵심 결과를 본문에 1줄 요약 (역할 분담: 본문은 정의 1줄 + 시사점, 부록은 디테일·증명·표)
3. Forward reference는 가능하면 제거. 정말 필요한 경우만 한 번.

판정: 섹션 참조 **0개** 권장. 1~2개는 ⚠. 3개 이상이면 자기 완결성 ✗.

### 중복 시 패러프레이징

같은 내용이 두 섹션에 반복되면 한쪽은 정의·다른 쪽은 활용 시점으로 **역할 분담**. 동일 표현 그대로 복붙 ✗.

## 단문 원칙 — One Sentence, One Role (Hard Rule) ★

원칙 2("하나의 문장은 하나의 생각")의 강한 형태. 단락 역할을 분명히 하려면 **문장 단위에서 카테고리가 정확히 하나**여야 한다.

### 강제 규칙

1. **한 문장에 카테고리 2개 이상이면 무조건 두 문장으로 분할.**
   - 검출: 문장 안에 `정의 + 인과`, `비교 + 평가` 등 두 서술 방식이 동시에 들어 있는가
   - 처리: 코치/리라이트는 즉시 분할 예시를 제시한다. 하이브리드 라벨(`[정의(+인과)]`)은 **사용 금지**.
2. **문장 길이 가이드** — KO 50자 / EN 20 words 이내가 단문 디폴트.
   - 길이만으로 ✗는 아니지만, 길이 + 카테고리 2개가 함께 잡히면 우선순위 최상으로 분할 권고.
3. **종속절·삽입절 정리** — `-며 / -고 / -는데 / -지만`으로 두 절을 잇고 각 절이 다른 카테고리면 분할.
   - 시간·장소 부사절, 인용절은 카테고리 외로 인정해 단일 카테고리 유지 가능.
4. **한 문단 안 단문 비율** — 5문장 단락 기준 단문(50자 이내) 비율 60% 이상 권장. 미만이면 prose가 무거워진다.

### 합격/불합격 예시

| 원문 | 카테고리 분석 | 판정 | 처리 |
|---|---|---|---|
| 본 연구는 X를 제안한다. | [정의] | ✓ | 유지 |
| 본 연구는 X를 제안하여, Y의 한계를 보완한다. | [혼합:정의+인과] | ✗ | 두 문장으로 분할 |
| 본 연구는 X를 제안한다. 이 제안은 Y의 한계를 직접 다룬다. | [정의] / [인과] | ✓ | 분할 결과 |
| X는 Y와 달리 Z를 더 잘 처리한다. | [혼합:비교+평가] | ✗ | "X는 Y와 다르다."[비교] / "X는 Z를 Y보다 더 잘 처리한다."[평가] |
| 2024년 보고된 GPT-4 결과는 Z를 보여준다. | [보고] (시간 부사절은 카테고리 외) | ✓ | 유지 |

### 왜 단문인가 — 세 가지 이유

1. **단락 진단이 작동한다.** 권장 흐름(정의 → 분석 → 과정)을 점검하려면 한 문장이 한 자리만 차지해야 한다. 두 카테고리 문장은 흐름 분석을 무력화한다.
2. **두괄식이 살아난다.** 첫 문장이 thesis인데 그 안에 인과·비교가 끼면 두괄식 효과가 흐려진다.
3. **AI 티가 사라진다.** "것이다"·"~을 통해"·"~함으로써" 같은 패턴은 두 카테고리를 한 문장에 우겨 넣을 때 가장 자주 등장한다. 단문 강제는 이 패턴들의 진입로를 막는다.

상세 출력 규약은 [coach-persona.md](coach-persona.md)의 "한 문장 한 역할 — 단문 강제" 절 참조.

## 퇴고 시 점검 사항 (Notion 4주차)

각 글을 다 쓴 뒤 4단계로 점검.

### 1. 주제 점검
- 예상 독자를 고려했는가
- 글의 목표가 제시되었는가

### 2. 구조 점검
- 문서가 하나의 주제로 작성되어 있는가
- 보고서 작성 목적·목표가 뚜렷한가
- 결론을 쉽게 이해하고 읽을 수 있게 작성했는가

### 3. 단락 점검
- 하나의 논제·주제를 사용하고 있는가
- 주제를 바르게 전달하도록 단락 배열되었는가
- 단락의 논리를 파악하기 쉬운가

### 4. 표현 점검
- 한 문장에 하나의 논리인가
- 논제를 바르게 전달하는 문장 배열인가
- 문장의 주어와 서술어가 명확한가
- 빼야 할 수식어는 없는가
- 생략해도 좋을 문장·어구는 없는가
