# Talk Script Clarity

발표 대본을 **한 번 듣고 끝나는 청중**에게 맞춘다. 읽는 글은 독자가 되돌아가 다시 읽을 수
있지만, 듣는 글은 지나가면 끝이다. 그래서 같은 내용이라도 반복, 은유, 숫자, 문장 길이를
읽는 글과 다르게 다룬다.

이 원칙은 최예진 교수의 TED 발표("Why AI is incredibly smart and shockingly stupid", 2023)의
구성 방식을 참고해 정리했다. 발표 원문은 싣지 않는다. 원칙은 이 저장소 작업자가 다시
정리한 것이며, 원 발표자의 공식 지침이 아니다.

## When to use

- 슬라이드는 있고 대본(speaker notes)을 다듬고 싶을 때
- "자연스럽게", "크리스탈 클리어하게", "귀로 듣기 쉽게" 고쳐 달라는 요청
- 덱 순서를 바꾼 뒤 대본 앞뒤가 이어지는지 점검할 때
- 디펜스·학회·랩세미나 리허설 전 마지막 점검

## When NOT to use

- 덱을 처음부터 만드는 일 → `academic-slides-iterative`
- 논문 문단 윤문 → `paper-section-rewrite` (읽는 글 규칙이 다르다. 아래 "읽는 글과 다른 점")
- 사실관계·수치 자체를 고치는 일. 이 스킬은 말하는 방식만 바꾼다

## 7원칙

### 원칙 1. 한 문장 주제를 처음과 끝에 박는다

발표 전체가 남길 그림을 한 문장으로 쓴다. 이 문장은 첫 장(또는 첫 1분)에 나오고, 결론 장과
마지막 장에서 거의 같은 말로 다시 나온다. 결론 장에서는 이 문장을 따로 떼어 말하고 잠시
멈춘다. 장(section)마다도 한 줄 요약을 두고, 장 요약들을 이으면 발표 주제 문장이 되는지 본다.

- 점검: 첫 장 주제 문장과 결론 장 주제 문장을 나란히 놓고 같은 말인지 본다.
- 실패 모양: 결론에서 처음 듣는 새 표현으로 요약한다. 청중은 같은 이야기인지 모른다.

### 원칙 2. 큰 은유 하나를 처음부터 끝까지 끌고 간다

발표의 문제의식을 담는 은유 하나를 고른다(예: "익숙한 풀이로 빠지는 함정"). 이 은유는
① 앞에서 심고, ② 이름을 붙이고, ③ 중간 장마다 같은 단어로 다시 부르고, ④ 결론과 마지막 장에서
회수한다. 은유 단어는 다른 말로 바꾸지 않는다.

- 산출물: **은유 회수 지도** — 은유가 등장하는 장 번호와 그 장에서의 역할(심기/이름/회수/마무리).
- 점검: 지도에서 빈 구간이 1/3을 넘으면 중간 회수 지점을 하나 더 만든다.
- 은유가 없으면 대본의 반복 단어와 문제의식에서 후보 2~3개를 제안한 뒤 하나를 고른다.

### 원칙 3. 핵심 개념마다 청중이 머릿속에서 풀어 볼 예제를 둔다

청중이 머릿속으로 직접 해 볼 수 있는 일상 예제나 비유를 먼저 보여 주고, 그다음 데이터를
보여 준다. 순서는 **예제 → 모델(또는 방법)이 하는 일 → 왜 그런가 → 무슨 뜻인가**.

- 대상: 발표의 핵심 주장 2~3개. 모든 장에 넣지 않는다.
- 좋은 예제의 조건: 전공 지식 없이 10초 안에 떠올릴 수 있다. 개념의 핵심 차이 하나만 보인다.
- 예: "온도를 올리는 건 메뉴판 글씨를 흐리게 하는 것. 1번 메뉴는 여전히 1번이다. RSP는 메뉴판
  순서를 섞는다."

### 원칙 4. 주장 하나에 숫자 하나

말로 하는 숫자는 기억에 남지 않는다. 주장마다 가장 중요한 숫자 하나(많아야 대비 한 쌍)만
말하고, 나머지는 슬라이드에 둔다.

- 기준: 장당 말하는 숫자 ≥ 8개면 경고, 장당 숫자가 대비 두 쌍을 넘으면 덜어낸다.
- 덜어내는 법: 정밀한 값은 어림말로("2만 게임 가까이", "다섯 배 넘게", "두 배로"),
  설정 숫자(샘플 수, 반복 횟수)는 슬라이드로, 비교 대상이 셋 이상이면 양 끝만 말한다.
- 안전장치: 숫자를 어림으로 바꿀 때 방향과 크기가 원래 값과 맞는지 반드시 확인한다.
  "절반이 넘는 57.8%"처럼 어림과 정확한 값을 같이 말하는 것은 허용.

### 원칙 5. 용어는 처음 나올 때 풀고, 한 개념에는 이름 하나

- 약어·전문 용어는 처음 말할 때 쉬운 말을 붙인다("희소 오토인코더, 줄여서 SAE",
  "작은 추가 가중치만 학습하는 LoRA").
- 수식 용어(로짓 간격, 상한, 순위 상관, 항진식 등)는 일상어로 바꾸거나 한 번 정의한다
  ("1등 후보와 나머지 후보의 점수 차", "많아야 이만큼", "1이면 순서가 하나도 안 바뀐 것").
- 한 개념에 이름 하나. 논문 용어와 발표 용어가 다르면 한 번만 연결한다
  ("논문에서는 주입이라고 하는데, 오늘은 붙이기라고 부를게요"). 이후로는 바꾸지 않는다.
- 점검: 같은 대상을 부르는 이름 묶음(예: 주입/붙이기/끼워 넣기, 분기/갈림길/갈래)의 등장 횟수를 세어
  한 이름이 압도하는지 본다.

### 원칙 6. 개수를 미리 알리고, 장 사이에 다리를 놓는다

- 여러 개를 말할 때는 개수를 먼저 말한다("세 가지 질문", "조건이 두 개").
- 장의 마지막 문장은 다음 장의 질문이 된다. 다음 장 첫 문장은 앞 장 마지막 말을 받아 출발한다.
- 같은 접속어("그런데", "그래서")가 장 경계에서 연달아 나오지 않게 한다.
- 순서를 바꾸거나 장을 합친 뒤에는 반드시 전체를 통으로 다시 읽는다. 이음새는 대개 바꾼 자리
  바로 앞뒤에서 깨진다.

### 원칙 7. 짧은 문장, 결론 장은 가장 짧게

- 한 문장에 생각 하나. 한국어 50자를 넘는 문장은 쪼갤 후보다.
- 장별 짧은 문장(≤ 50자) 비율 ≥ 60%. 다만 접속 없이 짧은 문장만 네 개 이상 이어지면
  개조식처럼 들리므로 원인과 결과는 한 문장으로 묶는다.
- 결론 장(과 마지막 장)은 발표에서 문장이 가장 짧아야 한다. 주제 문장 앞에 "(잠시 멈춤)"을 표시한다.

## 작업 순서

```
Step 0  입력 정리      대본을 장 단위로 나눈다. 형식: [번호 · 제목 · 초] 본문
Step 1  주제·은유      한 문장 주제와 큰 은유를 뽑는다(없으면 후보 제안 후 선택)
Step 2  은유 회수 지도  은유가 등장하는 장과 역할 표. 빈 구간 표시
Step 3  측정(전)        scripts/clarity_metrics.py 실행. 숫자·문장 길이·용어·이름 묶음·은유 등장
Step 4  장별 점검·수정  7원칙 체크리스트(references/checklist.md)로 장마다 고친다
Step 5  이음새 통독     전체를 처음부터 끝까지 읽으며 장 경계만 본다(원칙 6)
Step 6  측정(후)·보고   같은 스크립트로 다시 재고 전후 표를 낸다. 장 시간 변화도 적는다
```

### Step 0 — 입력 정리

- 대본이 HTML 덱의 `data-speaker-notes`에 있으면 그대로 읽는다. Docs·마크다운이면
  `[번호 · 제목 · 초]` 머리말 단위로 나눈다.
- 슬라이드 화면 글자도 함께 본다. 대본과 화면이 다른 숫자를 말하면 화면을 기준으로 맞춘다.

### Step 3 — 측정

```bash
python scripts/clarity_metrics.py deck/index.html --metaphor 함정 \
    --aliases "주입,붙이기,끼워 넣" --aliases "분기,갈림길,갈래"
python scripts/clarity_metrics.py script.md --metaphor 함정      # [NN · 제목 · 초] 형식
```

출력: 장별 글자 수, 문장 평균 길이, 짧은 문장 비율, 숫자 개수(≥ 8 경고), 전문 용어 목록,
이름 묶음 카운트, 은유 등장 장 목록, 작업 이력 단어, 전체 요약. 플래그는 판단 재료다.
순위 이름("1번 메뉴")이나 실험 반복 설명("다시 돌려도")처럼 규칙에 걸려도 문제가 아닌 경우가 있다.

### Step 4 — 장별 수정 규칙

- **사실과 수치는 바꾸지 않는다.** 바꾸는 것은 말하는 방식뿐이다. 어림말로 바꾼 숫자는 원래 값과
  방향·크기가 맞는지 확인한다.
- 그림을 가리키는 말("왼쪽", "위쪽", "빨간 선")은 실제 슬라이드 배치와 맞는지 확인한다. 슬라이드를
  고쳤다면 대본의 방향어도 다시 본다.
- 장 시간 표기(`[45초]`)는 글자 수 변화에 맞춰 고친다(한국어 구어 약 5~5.5자/초).
- 작업 경과 표현은 내용 이름으로 바꾼다("리뷰 대응 갱신" → "5 seed 평균", "리뷰에서 나와서" →
  "이 질문에 답하려고"). 청중은 작업 이력을 모른다.

### Step 6 — 보고 형식

```markdown
| 항목 | 전 | 후 |
|---|---|---|
| 말하는 숫자 합계 | 155 | 132 |
| 짧은 문장 비율 | 77% | 82% |
| 풀지 않은 전문 용어 | 로짓 간격, 항진식, … | 0 |
| 은유 등장 장 | 0 | 11 (1, 10, 11, 13, 23, …, 50) |
| 장 머리말 시간 합계 | 37분 20초 | 36분 50초 |
```

장별 변경은 "장 번호 · 고친 원칙 · 한 줄 요약"으로 적는다.

## 읽는 글과 다른 점 (paper-section-rewrite와 함께 쓸 때)

이 스킬은 `paper-section-rewrite`의 Level 1~4(내용 → 문단 간 → 문단 내 → 문장) 정신을
따른다. 남는 그림, 문장 연결, 비전공자 게이트, 이력 독립성은 그대로 적용한다.
다만 귀로 듣는 글이라 아래 네 가지는 **반대로** 적용한다.

| 지점 | 읽는 글(paper-section-rewrite) | 듣는 글(이 스킬) |
|---|---|---|
| 반복 | 같은 말 세 번은 지리멸렬 | 주제 문장·은유는 일부러 처음·중간·끝에 반복 |
| 개념어 | 5회 이상이면 회전 권고 | 은유 단어와 정의한 핵심 용어는 절대 회전하지 않음 |
| 문체 | 구어체 혼입은 register ⚠ | 구어체가 기본. "~요", "~죠" 허용 |
| 개수 신호 | "첫째, 둘째"는 기계적 병렬 ⚠ | 개수 예고는 필수 장치 |
| 부정형 lead | 문단 첫 문장 부정형 0 | 기대를 뒤집는 부정형 훅은 허용(장당 1회) |

그 밖에 `humanize-korean`의 번역투·계사 대용 금지 규칙은 그대로 적용한다.

## 함께 쓰는 스킬

- `academic-slides-iterative` — 덱을 만든 뒤 동반 talking points의 "슬라이드별 대본"을 이 스킬로 점검
- `paper-section-rewrite` — 같은 내용을 논문으로 쓸 때. 위 표의 차이만 기억하면 된다
- `humanize-korean` — AI 티 나는 한국어 표현 정리
