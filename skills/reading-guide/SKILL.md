# Reading Guide Skill

논문 PDF를 분석하여 "읽기 전 내비게이션"을 생성한다. 사용자가 직접 논문을 읽고 성장하는 것이 목적이므로, 내용을 대신 요약하지 않고 구조와 용어를 미리 안내하여 읽기 효율을 높인다.

## Workflow

```
[입력: 논문 PDF 또는 Zotero library.json에서 새 논문 감지]
      ↓
[1] 논문 전문 읽기 (PDF 텍스트 추출)
      ↓
[2] 읽기 가이드 생성
    ├── Zotero 태그 추천
    ├── 핵심 질문 요약 (2~3문장)
    ├── 논문 구조 미리보기 테이블
    ├── 용어 사전
    ├── (양적연구일 경우) 연구 모형 다이어그램
    └── 워크시트 (능동적 읽기용 질문)
      ↓
[3] Guides 폴더에 저장
      ↓
[4] 품질 체크리스트 검증
```

## Phase 1: 논문 읽기

PDF를 pymupdf 등으로 텍스트 추출하여 전문을 읽는다. 이 단계에서 파악할 것:

1. **논문 유형**: 리뷰논문, 양적연구, 질적연구, 메타분석, 이론 논문 등
2. **섹션 구조**: 각 섹션의 제목, 페이지 범위, 역할
3. **핵심 변수**: 독립변수, 매개변수, 종속변수 (양적연구일 경우)
4. **전문 용어**: 사전 지식 없이 이해하기 어려운 용어 목록
5. **핵심 테이블/그림**: 논문의 심장이 되는 테이블이나 그림 번호

## Phase 2: Zotero 태그 추천

논문 내용을 바탕으로 Zotero에 붙일 태그를 3~7개 추천한다.

**태그 선정 규칙**:
- 한국어로 통일 (사용자가 검색할 때 자연스럽게 떠올리는 언어)
- 고유명사/이론명은 필요시 원어 병기 태그 추가 (예: `좌절-공격 가설` + `frustration-aggression`)
- 양적연구일 경우 독립변수, 매개변수, 종속변수를 각각 태그로 포함
- 연구 유형 태그 포함 (예: `양적연구`, `리뷰논문`, `질적연구`, `메타분석`)
- 분야 태그 포함 (예: `사회심리학`, `상담`, `발달심리`, `가족복지`)

**태그 테이블 형식**:

| 태그 | 이유 |
|------|------|
| `{태그명}` | {왜 이 태그를 다는지 한 줄 설명} |

사용자가 Zotero에서 바로 복사-붙여넣기 할 수 있도록 태그명은 백틱으로 감싼다.

## Phase 3: 읽기 가이드 본문

### 3.1 "이 논문이 뭘 하려는 건가?"

2~3문장으로 배경과 맥락을 설명한다. 이 분야를 모르는 사람도 "아, 그런 문제가 있구나"라고 느낄 수 있는 수준. 학술 용어 대신 일상 언어를 쓴다.

그 아래에 **한 줄 요약**을 붙인다: 논문의 핵심 주장을 일상 언어로 한 문장.

### 3.2 논문 구조 미리보기

| 페이지 | 섹션 | 역할 | 읽기 팁 |
|--------|------|------|---------|
| p.XX | {섹션명} | {이 섹션이 하는 일} | {속도 조절 + 집중 포인트} |

**읽기 팁 작성 규칙**:
- 속도 안내: "가볍게 훑기", "천천히 읽기", "집중해서 읽기"
- 집중 포인트: "정의에 집중", "표 3만 확인하면 됨", "결론 문단만 읽기"
- ⭐ 표시로 가장 중요한 섹션 1~2개 강조
- 논문이 길 때: 건너뛰어도 되는 섹션 안내 ("이 부분은 나중에 필요할 때 돌아오면 됨")

### 3.3 미리 알아야 할 용어

| 용어 | 뜻 | 쉽게 말하면 |
|------|-----|------------|
| {영어 용어} ({한글}) | {학술적 정의} | {일상 비유나 쉬운 설명} |

**선별 기준**: 사전 지식 없이 이해하기 어려운 용어만 포함한다. 해당 분야 전공자라면 당연히 아는 기초 용어도 포함한다 (사용자가 구조화에 약점이 있으므로). "쉽게 말하면" 열에는 비유, 일상 상황, 또는 한 줄 비교를 사용한다.

### 3.4 연구 모형 다이어그램 (양적연구일 경우)

구조방정식, 회귀분석, 매개/조절 모형 등의 연구 모형이 있을 경우, ASCII 다이어그램으로 변수 간 관계를 시각화한다. 사용자가 "어떤 화살표가 유의하고 어떤 건 아닌지"를 읽으면서 직접 채울 수 있게 빈 상태로 둔다.

### 3.5 워크시트

논문을 읽으면서 빈칸을 채우는 형식의 질문을 만든다. 자유 메모가 아니라 정해진 질문에 답하는 구조이므로 집중이 흐려지는 것을 방지한다.

**워크시트 질문 작성 규칙**:
- 각 질문은 논문의 특정 섹션/페이지를 가리킨다 (어디서 답을 찾을지 명확히)
- 단순 사실 확인이 아닌 "왜?"와 "어떻게?"를 묻는 질문 위주
- 양적연구일 경우 "어떤 경로가 유의한지 O/X로 표시" 같은 구조화 질문 포함
- 질문 수는 논문 길이에 비례: 짧은 논문(~10p)은 Q1~Q5, 긴 논문(20p+)은 Q1~Q8
- 마지막 두 질문은 항상 고정:
  - **"내 생각"**: 읽으면서 가장 흥미롭거나 의문이 든 부분
  - **"모르겠는 부분"**: 이해가 안 되거나 더 설명이 필요한 부분
- 모르겠으면 `?`로 남겨두라고 안내한다

## Phase 4: 저장

**파일명 규칙**: `{대표저자}_{연도}_읽기가이드.md`
- 한국어 논문 예: `장혜림_2013_읽기가이드.md`
- 영어 논문 예: `Berkowitz_1989_읽기가이드.md`

**저장 위치**: Obsidian vault의 `Guides/` 폴더
- vault 경로는 사용자의 workspace 폴더를 따른다
- Guides 폴더가 없으면 자동 생성

## Phase 5: 워크시트 리뷰 (사용자가 돌아왔을 때)

사용자가 워크시트를 채워서 돌아오면:
1. 맞는 부분은 확인해준다
2. `?`로 남긴 부분은 논문 원문을 근거로 설명해준다
3. 놓친 포인트를 짚어준다
4. 사용자의 "내 생각"에 대해 대화한다
5. 필요하면 survey-paper 스킬을 호출하여 최종 서베이 노트를 생성한다

## 품질 체크리스트

생성 후 자체 검증 (모두 ✅ 여야 완료):

- [ ] Zotero 태그가 3~7개이고, 한국어이며, 이유가 명시되어 있는가?
- [ ] "이 논문이 뭘 하려는 건가?"가 전문 용어 없이 이해 가능한가?
- [ ] 논문 구조 미리보기가 모든 주요 섹션을 포함하는가?
- [ ] ⭐ 표시로 가장 중요한 섹션이 강조되어 있는가?
- [ ] 용어 사전의 "쉽게 말하면" 열이 실제로 쉬운가?
- [ ] 워크시트 질문이 논문의 특정 페이지/섹션을 가리키는가?
- [ ] 워크시트의 마지막 두 질문("내 생각", "모르겠는 부분")이 포함되어 있는가?
- [ ] 전체 가이드가 5분 내 읽을 수 있는 분량인가?
- [ ] Guides 폴더에 올바른 파일명으로 저장되었는가?
