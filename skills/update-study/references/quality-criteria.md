# Writing Quality Criteria

실험 해석 글의 품질을 평가하는 상세 기준입니다.

---

## 평가 기준 (총 100점)

### 1. Definition-First (30점)

**모든 전문 용어와 새로운 개념은 사용 전에 정의되어야 한다.**

| 점수 | 기준 |
|------|------|
| 30 | 모든 용어가 "X는 Y이다" 형태로 정의됨 |
| 24 | 90% 이상 정의됨, 일부 누락 |
| 18 | 70% 이상 정의됨 |
| 12 | 50% 이상 정의됨 |
| 6 | 30% 이상 정의됨 |
| 0 | 대부분 정의 없이 사용 |

**좋은 예**:
```
WeaverStyleCompressor는 Weaver LLM을 대체하여 context를 latent로 압축하는
경량 모듈이다. 이 모듈은 Low-Rank Self-Attention과 SwiGLU MLP로 구성된다.
```

**나쁜 예**:
```
WeaverStyleCompressor를 사용하여 압축을 수행했다.
(→ 무엇인지 정의 없음)
```

**체크 방법**:
1. 문서에서 전문 용어 목록 추출
2. 각 용어의 첫 등장 위치 확인
3. 해당 위치에서 "X는 Y이다" 형태 정의 존재 여부 확인

---

### 2. Topic-First Paragraphs (25점)

**모든 문단은 핵심 주장 또는 결과로 시작해야 한다.**

| 점수 | 기준 |
|------|------|
| 25 | 모든 문단이 두괄식 |
| 20 | 90% 이상 두괄식 |
| 15 | 70% 이상 두괄식 |
| 10 | 50% 이상 두괄식 |
| 5 | 30% 이상 두괄식 |
| 0 | 대부분 미괄식 또는 중괄식 |

**좋은 예**:
```
Evolve_h_only 모드는 87.34%의 정확도를 달성했다. 이는 baseline 대비
+3.21%p 향상이며, cross-attention 모드의 84.12%보다 높다. 이러한 결과는...
```

**나쁜 예**:
```
이번 실험에서는 여러 설정을 테스트했다. 먼저 baseline을 실행하고,
그 다음 evolve_h_only를 실행했다. 결과적으로 87.34%가 나왔다.
(→ 핵심이 마지막에 등장)
```

**체크 방법**:
1. 각 문단의 첫 문장 추출
2. 첫 문장만 읽어도 문단 내용 파악 가능한지 확인
3. 핵심 수치/결론이 첫 문장에 있는지 확인

---

### 3. Compare-Contrast (20점)

**새로운 결과는 반드시 이전 결과와 비교되어야 한다.**

| 점수 | 기준 |
|------|------|
| 20 | 비교 테이블 + 차이 분석 문단 모두 있음 |
| 16 | 비교 테이블은 있으나 분석이 부족함 |
| 12 | 텍스트로 비교하나 테이블 없음 |
| 8 | 일부 비교만 있음 |
| 4 | 최소한의 비교만 언급 |
| 0 | 비교 없이 결과만 나열 |

**필수 비교 대상**:
- Baseline (vanilla model)
- 직전 실험 (E{N-1})
- 동일 계열 최고 성능 실험

**좋은 예**:
```
| Experiment | Accuracy | Δ |
|-----------|----------|---|
| Baseline | 84.13% | baseline |
| E12 (cross-attn) | 84.12% | -0.01%p |
| **E13 (evolve_h_only)** | 87.34% | +3.21%p |

E13은 E12 대비 +3.22%p 향상을 보였다. 이러한 차이는 context가
매 H-cycle마다 진화하여 점진적 정보 누적이 가능해졌기 때문으로 보인다.
```

**나쁜 예**:
```
실험 결과 87.34%의 정확도를 달성했다.
(→ 비교 대상 없음, 의미 해석 불가)
```

---

### 4. Insight Depth (15점)

**표면적 기술을 넘어 "왜"에 대한 분석이 있어야 한다.**

| 점수 | 기준 |
|------|------|
| 15 | 깊은 mechanism 분석 + 대안 가설 검토 |
| 12 | Mechanism 가설 제시 |
| 9 | "왜"에 대한 추측 있음 |
| 6 | 결과 해석은 있으나 원인 분석 부족 |
| 3 | 결과 기술만 있음 |
| 0 | 수치 나열만 있음 |

**Insight 깊이 단계**:

1. **수치 나열** (0점): "87.34%를 달성했다"
2. **결과 기술** (3점): "baseline보다 높다"
3. **간단한 해석** (6점): "evolve_h_only가 더 효과적이다"
4. **원인 추측** (9점): "context 진화가 성능 향상에 기여했을 것이다"
5. **Mechanism 가설** (12점): "H-cycle 경계에서의 context 업데이트가 점진적 정보 누적을 가능하게 하여..."
6. **대안 검토** (15점): "이 결과는 A 때문일 수도 있고, B 때문일 수도 있다. A를 검증하려면..."

---

### 5. Minimal Adjectives (10점)

**불필요한 수식어 없이 구체적 수치로 표현해야 한다.**

| 점수 | 기준 |
|------|------|
| 10 | 모든 주장이 수치로 뒷받침됨 |
| 8 | 대부분 수치 기반, 일부 형용사 |
| 6 | 절반 정도 수치 기반 |
| 4 | 형용사 다수, 일부 수치 |
| 2 | 대부분 형용사 |
| 0 | 구체적 수치 없음 |

**금지 표현 → 대체 표현**:

| 금지 | 대체 |
|------|------|
| 매우 높은 정확도 | 87.34% 정확도 |
| 상당한 향상 | +3.21%p 향상 |
| 크게 개선됨 | 2.3배 개선 |
| 빠르게 수렴 | 500 step 내 수렴 |
| 안정적인 학습 | grad_norm < 1.0 유지 |

---

## 총점 계산

```
Total = Definition-First + Topic-First + Compare-Contrast + Insight + Adjectives
      = 30 + 25 + 20 + 15 + 10
      = 100

통과 기준: ≥ 80점
```

## 평가 예시

### 예시 1: 고품질 (92점)

```
WeaverStyleCompressor는 Weaver LLM을 대체하여 context를 latent로 압축하는
경량 모듈이다(Definition: ✓).

E13 (evolve_h_only)는 87.34%의 정확도를 달성했다(Topic-First: ✓).
이는 baseline (84.13%) 대비 +3.21%p, E12 (cross-attn, 84.12%) 대비
+3.22%p 향상이다(Compare: ✓).

이러한 향상은 H-cycle 경계에서의 context 업데이트가 점진적 정보 누적을
가능하게 했기 때문으로 추정된다. Cross-attention이 매 step context를
읽는 것과 달리, evolve_h_only는 5 L-cycle마다 context를 업데이트하여
더 안정적인 정보 흐름을 형성한다(Insight: ✓).
```

- Definition-First: 28/30 (대부분 정의됨)
- Topic-First: 25/25 (모든 문단 두괄식)
- Compare-Contrast: 20/20 (테이블 + 분석)
- Insight: 12/15 (mechanism 가설 있음)
- Adjectives: 7/10 (일부 형용사 있으나 대부분 수치)

**Total: 92/100 → PASS**

### 예시 2: 저품질 (42점)

```
이번 실험에서 여러 설정을 테스트해 보았다. evolve_h_only를 사용했고
결과가 꽤 좋았다. Cross-attention보다 성능이 상당히 높았고 학습도
안정적이었다. 아마도 context 진화가 도움이 된 것 같다.
```

- Definition-First: 0/30 (용어 정의 없음)
- Topic-First: 5/25 (미괄식)
- Compare-Contrast: 4/20 (최소한의 언급만)
- Insight: 6/15 (피상적 해석)
- Adjectives: 2/10 (수치 없음, 형용사 다수)

**Total: 42/100 → FAIL**

## 수정 가이드

### Critical Issues (즉시 수정 필요)

1. **Definition Missing**: 용어 정의 추가
2. **No Source Citation**: 출처 추가
3. **Topic-Last Paragraph**: 문단 구조 재배치

### Warnings (개선 권장)

1. **Shallow Insight**: "왜" 분석 추가
2. **Missing Comparison**: 비교 테이블 추가
3. **Excessive Adjectives**: 수치로 대체

### Minor Issues (선택적 개선)

1. **Verbose Expression**: 문장 간결화
2. **Missing Context**: 배경 설명 추가
