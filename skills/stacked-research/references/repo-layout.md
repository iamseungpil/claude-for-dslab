# 저장소 정리 — 수명 구역과 이관 규약

## 왜 정리가 안 되나 — **삭제 기준이 없어서다**

게으름이 아니다. 실측: 실험 스크립트 **59개 중 43개가 고아**(어디서도 import 안 됨)인데
**하나도 못 지웠다.** 이유는 하나 —

> **수명이 다른 파일이 같은 디렉터리에 섞여 있으면 *"이거 지워도 되나?"* 에 답할 수 없다.
> 답할 수 없으면 아무것도 안 지운다. 그래서 620개가 된다.**

`experiments/arc/` 에 정본 트레이너(수명: 프로젝트 전체)와 일회성 probe 35개(수명: 며칠)와
판정 스크립트(수명: 영구)가 **같은 곳**에 있었다.

## 수명 다섯 구역

| 구역 | 수명 | 변경 | 리뷰 | git | 삭제 규칙 |
|---|---|---|---|---|---|
| **core** 라이브러리 | 프로젝트 전체 | 드묾 | **필수** | ✅ | 대체된 것만, 승인 후 |
| **runners** 진입점 | 프로젝트 전체 | 드묾 | 필수 | ✅ | 거의 안 지움 (2개면 충분) |
| **experiments** 단계·설정 | 실험 하나 | 실험마다 | 가벼움 | ✅ | 판정 후 `[죽음]` 표시하고 **남긴다** |
| **probes** 일회성 진단 | **며칠** | 항상 | 없음 | ✅ | **기한 지나면 자동 archive** |
| **artifacts** ckpt·로그·런 | 재생성 가능 | 항상 | 없음 | ❌ | git 밖. 자유롭게 지움 |

**★구역이 갈리면 삭제 규칙이 자동으로 정해진다.** 그게 정리의 전부다.

## 표준 배치

```

├── CONTRIBUTING.md            ← 실험 추가 원칙 (SKILL §5)

├── src/<pkg>/                 [core] 잠금·테스트 필수
│   ├── <arch>.py                정본 (sha 고정)
│   ├── losses/                  파일 하나 = 개념 하나 · 레지스트리 등록
│   ├── rulers/                  공통 시그니처
│   ├── conditioning/            ★가설공간 축이 사는 곳
│   └── domains/                 데이터·특징기·평가

│
├── experiments/               [실험 = 단계별 디렉터리]
│   ├── README.md                ★사다리 한 장 — 어느 단계가 살고 죽었나
│   └── <domain>/<NN>_<name>/
│         README.md              물음 · 판정 · CLAIMS 포인터 · 상태 배지

```

## 실험 디렉터리를 **단계별**로 — 이야기가 보이게

`experiments/` 는 알파벳 순 파일 더미가 아니라 **시도의 순서**여야 한다.
새로 온 사람이 물을 것은 하나다 — ***"여기서 뭘 해봤고, 뭐가 죽었고, 지금 어디인가?"***

```
experiments/<domain>/
  01_<접근>/   [죽음]  ← 왜 죽었는지 README 첫 줄에
  02_<접근>/   [현역]
  03_<접근>/   [다음]
```

**각 단계 README 는 다섯 줄이면 된다:**
```markdown
# 02_subtb_champion  [현역]
**물음**: <한 문장>
**판정**: <한 문장 + 수치 + 기준선>
**주장**: CLAIMS C-0xx
**재현**: `runners/train.py --config experiments/.../cell_000.yaml`
```

⛔**죽은 단계를 지우지 마라.** 같은 자리를 다시 제안하는 것을 막는 것이 그 디렉터리의 값이다.
지우는 것은 **probes** 와 **artifacts** 뿐이다.

## 이관 규약 — 협업 저장소에서 안전하게

1. **★남의 디렉터리를 옮기지 않는다.** 다른 협업자의 경로 의존을 깨는 것은 단독 결정이 아니다.
   두 프로그램이 한 저장소에 있으면 **경계를 README 에 명시**하고 우리 것만 정리한다.
2. **★이동 커밋과 수정 커밋을 절대 섞지 않는다.** 섞이면 리뷰가 불가능하다.
   `git mv` 로 이력을 보존하고, 이동만 하는 커밋을 따로 만든다.
3. **구 경로는 shim 으로 남긴다.** 재수출 + `DeprecationWarning`. 돌던 스크립트가 안 깨진다.
4. **정리 전에 기준선을 커밋한다.** 안 하면 이동 후 무엇이 바뀐 건지 못 본다.
5. **★매 커밋 후 회귀 벤치(G5).** 재현 수를 하나 정해 놓고 이동마다 확인한다.
   안 맞으면 그 커밋을 되돌린다.
6. **잠금은 확장 지점을 함께 준다.** 정본 파일만 sha 고정하고 트레이너를 안 잠그면
   **잠긴 파일을 피해 포크가 생긴다.** 실측: 트레이너가 1,138행 vs 2,814행으로
   6주간 두 갈래로 살았고, 챔피언이 도는 코드가 정본 트리에 **없었다.**

## git 정책 — 무엇을 커밋하나

| | 커밋 | 이유 |
|---|---|---|
| **기록** (md·json·tsv) | ✅ | ★**결과 json 을 빼면 주장만 있고 증거가 없다.** 실측: 결과 111개가 미추적인 채로 그것을 인용하는 판정문만 커밋돼 있었다 |
| **설정** (yaml) | ✅ | 재현의 전부 |
| **코드** | ✅ | — |
| **산출물** (pt·log·runs·wandb) | ❌ | 재생성 가능 · 용량 |

**`.gitignore` 에 정책을 주석으로 적는다.** 암묵이면 다음 사람이 판단을 다시 한다.

## 정리 후 자기점검 넷

```bash
# ① 고아: 아무도 import 안 하는 core 가 있나
# ② 포크: 같은 basename 이 두 곳에 있나
find . -name "*.py" -not -path "*/.git/*" -printf "%f\n" | sort | uniq -d
# ③ 미배선: 정의됐지만 호출 0인 공개 함수
# ④ 회귀: 재현 수가 그대로인가  ← 이게 통과해야 정리가 끝난 것이다
```

⚠**넷 중 ④만이 정리의 성공 조건이다.** 나머지 셋은 깔끔함이고, ④는 **안 깨뜨렸다는 증거**다.
