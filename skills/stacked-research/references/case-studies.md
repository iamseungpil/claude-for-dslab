# 근거 — 이 규칙들이 없어서 무엇을 잃었나

**규칙이 과하게 느껴지면 여기부터 읽어라.** 전부 실측이다.

두 프로젝트에서 **독립으로** 같은 실패가 났다. 코드도 도메인도 목표도 다르다.
그래서 이건 프로젝트 특유의 병이 아니라 **작업 방식의 결함**이고, 그래서 스킬이다.

- **P-A**: `MatterGPT_RL` — 무증강 few-data 규칙 학습 (GRAM/TRM · 스도쿠·ARC·크리스탈)
- **P-B**: `arc-agi-3-symbolica-bestiary` — 얼린 LLM + 스킬 라이브러리 (TTSO)

## 1. 배선 실패 — *"코드에 있는데 0회 발화"*

| | P-A | P-B |
|---|---|---|
| | `--kl-beta` 가 **선언·기록되지만 그래디언트에 도달 안 함**(몇 달). `y_feat` 미전달 → posterior 경로 사망 | `set_code()` 라이브 호출부 2개, 둘 다 입고 **전**, 이번 런 **0회 발화** — 244개 버전 전부 v1 |
| | `loss_equiv_consistency` **구현 완료 · 호출 0** (두 트리 모두) | `CONSENSUS` 절 59라운드 중 **0회** 렌더 (잘린 게 아니라 안 만들어짐) |
| | 챔피언 트레이너가 **정본에 없는 포크**(1,138행 vs 2,814행)에서 6주간 운행 | `plan` kind 레코드 **0개** · `top_mechanic` 결과가 소비처에 **안 닿음** |

> P-B 세션의 문장: ***"기계는 맞게 만들어져 있고, 아무도 호출하지 않습니다."***

**⇒ G2(발화 검사).** 단위 테스트는 *"함수가 옳게 도는가"* 를 보지 *"라이브 경로에서 호출되는가"* 를
안 본다. 그래서 위 9건을 **전부 통과시켰다.**

**잃은 것**: P-A 는 노벨티 세 성분(MDL·자·증류)이 전부 꺼진 채로 11일 튜닝했다.
P-B 는 "스킬 수리가 안 된다"는 연구 결론을 냈는데 실은 수리 코드가 안 불린 것이었다.

## 6. 축이 잠긴 것을 아무도 안 셌다

P-A: §1이 **증강(데이터 축)** 을, §4가 **아키텍처(구조 축)** 를 금지했다.

그리고 남은 세 축(스케일·손실·조건화) 위 76번 탐색이 전역 최적에 도달 —
*"학습 성분이 최종지표를 움직인 도메인 **0/3**"*.

**⇒ 헌법 R4·R5.** 축을 잠글 때 **몇 개가 남는지 센다.**

## 7. 통제군 결측

P-A 사전등록 76건 중 통제군 명시 **47건** — **29건(38%) 결측**.

## 13. 성분 지도 없이 국소 수정 (⇒ SKILL §10 ⑥)

어느 채점기에 α/β를 쓰는 경로가 **여덟 개**였는데 **아무도 그것을 한 표에 놓은 적이 없었다.**
나란히 놓자마자 두 결함이 즉시 보였다 —

- **판정자가 두 곳에서 돌며** 서로의 미래항을 리셋하고,
- **형제 규칙이 서로의 saved/harmed 를 상쇄**해 맞혀도 0 · 틀려도 0이 된다.

**경로를 따로 읽으면 둘 다 안 보인다.**

⚠**국소적으로 옳은 수정들이 합쳐서 틀릴 수 있다.** 그 넷은 전부 그 시점에 옳았다 —
플래그는 다른 걸 안 깨려고, 두 번째 판정자는 그 자리에도 필요해서, 상수 코드는 dense
신호를 원해서, 기본 모드는 헌법이 요구해서. **각각 옳고, 합쳐서 "이 성분이 무엇을 재는가"를
한 문장으로 말할 수 없었다.**

## 14. 아이 언어 산출물이 잡은 오류 셋 (⇒ SKILL §13 30분 산출물)

- *"초록"* 을 쉽게 설명하려다 **한 단어를 세 뜻으로 써 왔음**을 발견했다 —
  테스트 통과 / 전 기록 정확일치 / 작업 완료. 세 번째는 **옳다는 뜻이 전혀 아닌데**
  같은 말로 보고해 왔다.
- 절단 규칙을 *"참고서 43권 중 8권만 갖고 시험 보기"* 로 바꾸자 **부조리가 즉시 보였고**,
  재보니 정말 **쓸 수 있는 것의 88%를 버리는** 설계였다. 전문용어로 쓰여 있는 동안에는 그럴듯했다.
- *"규칙이 많으니 하나만 남기자"* 를 풀어 쓰다 **개수 손실과 선택 손실을 분리**하게 됐고,
  재보니 후자가 전자의 **2.9배**였다. 줄일 것은 개수가 아니라 **고르는 눈**이었다.

**⇒ 설명을 미루면 오류가 숨는다.** 결과가 다 모인 뒤 한 번에 쓰는 설명은 이미 자기 틀 안에서 정리된 것이다.

## 15. 감사 넷을 다 돌려도 누락은 안 잡힌다 (⇒ SKILL §13 검사 ⑸ · 미결 인벤토리 · 누락 감사관)

0807 실측 — **이 스킬이 켜진 상태에서** 난 사고다:

- §13 10분 감사를 **한 번도 안 했고**, §2 게이트 여덟 중 **G2·G5 둘만** 쳤다.
- **G8(팔 정체)을 안 쳐서** — "복원했다"고 커밋된 기계가 **호출자 0** 이라
  그 팔이 통제군과 **바이트 동일**이었다.
- §12(지시를 즉시 체크리스트로)를 안 해서 — 지시 22건 중 **10건만 구현되고 9건이 조용히 빠졌다.**
- 범위 축소 두 번이 **"이유는 있었으나 말하지 않은"** 채 지나갔다.

진단: 기존 10분 검사 넷은 전부 *"돌고 있는 것이 맞나"* 를 묻는다.
*"선언된 것 대비 무엇이 없는가"* 를 묻는 칸이 **하나도 없었다** — 그래서 조용한 누락은
검사를 전부 통과한다. **없는 것은 어떤 존재 검사에도 안 걸린다.**

**⇒ 검사 ⑸(누락) + 미결 인벤토리(`BLOCK/OPEN/DECIDE/CLOSED`) + 병렬 감사 상설 누락 감사관 1팔.**
