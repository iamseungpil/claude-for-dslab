# Writing Quality Criteria

실험 보고서의 품질을 평가하는 상세 기준입니다.

---

## 평가 기준 (총 100점)

### 1. Definition-First (25점)

**모든 전문 용어와 새로운 개념은 사용 전에 정의되어야 한다.**

| 점수 | 기준 |
|------|------|
| 25 | 모든 용어가 "X는 Y이다" 형태로 정의됨 |
| 20 | 90% 이상 정의됨, 일부 누락 |
| 15 | 70% 이상 정의됨 |
| 10 | 50% 이상 정의됨 |
| 5 | 30% 이상 정의됨 |
| 0 | 대부분 정의 없이 사용 |

**좋은 예**:
```
Void turn filtering은 prompt 또는 response가 비어 있는 턴을 학습 데이터에서
제외하는 전처리 단계이다. 빈 시퀀스는 gradient에 노이즈를 유발하므로 제거한다.
```

**나쁜 예**:
```
Void turn filtering을 적용했다.
(→ 무엇인지 정의 없음)
```

---

### 2. Topic-First Paragraphs (20점)

**모든 문단은 핵심 주장 또는 결과로 시작해야 한다.**

| 점수 | 기준 |
|------|------|
| 20 | 모든 문단이 두괄식 |
| 16 | 90% 이상 두괄식 |
| 12 | 70% 이상 두괄식 |
| 8 | 50% 이상 두괄식 |
| 4 | 30% 이상 두괄식 |
| 0 | 대부분 미괄식 또는 중괄식 |

**좋은 예**:
```
Filter ON 조건에서 validation accuracy가 74.1%에 도달했다. 이는 Filter OFF (58.8%)
대비 +15.3%p 향상이며, 학습 후반부의 급격한 상승이 특징적이다.
```

**나쁜 예**:
```
이번 실험에서는 GSM8K 데이터셋을 사용하여 학습을 진행했다. 먼저 baseline을
실행하고, 그 다음 필터링을 적용했다. 결과적으로 74.1%가 나왔다.
(→ 핵심이 마지막에 등장)
```

---

### 3. Compare-Contrast (15점)

**새로운 결과는 반드시 이전 결과와 비교되어야 한다.**

| 점수 | 기준 |
|------|------|
| 15 | 비교 테이블 + 차이 분석 문단 모두 있음 |
| 12 | 비교 테이블은 있으나 분석이 부족함 |
| 9 | 텍스트로 비교하나 테이블 없음 |
| 6 | 일부 비교만 있음 |
| 3 | 최소한의 비교만 언급 |
| 0 | 비교 없이 결과만 나열 |

**필수 비교 대상**:
- Baseline (비교 기준)
- 동일 조건에서의 이전 실험
- 동일 계열 최고 성능 실험

---

### 4. Insight Depth (15점)

**표면적 기술을 넘어 "왜"에 대한 분석이 있어야 한다.**

| 점수 | 기준 |
|------|------|
| 15 | 깊은 mechanism 분석 + 대안 가설 검토 |
| 12 | Mechanism 가설 제시 |
| 9 | "왜"에 대한 추측 있음 |
| 6 | 결과 해석은 있으나 원인 분석 부족 |
| 3 | 결과 기술만 있음 |
| 0 | 수치 나열만 있음 |

**Insight 깊이 단계**:

1. **수치 나열** (0점): "74.1%를 달성했다"
2. **결과 기술** (3점): "baseline보다 높다"
3. **간단한 해석** (6점): "필터링이 효과적이다"
4. **원인 추측** (9점): "노이즈 gradient 제거가 성능 향상에 기여했을 것이다"
5. **Mechanism 가설** (12점): "비정상 턴을 제외함으로써 정상 패턴만 강화학습되어..."
6. **대안 검토** (15점): "이 결과는 A 때문일 수도 있고, B 때문일 수도 있다. A를 검증하려면..."

---

### 5. Minimal Adjectives (5점)

**불필요한 수식어 없이 구체적 수치로 표현해야 한다.**

| 점수 | 기준 |
|------|------|
| 5 | 모든 주장이 수치로 뒷받침됨 |
| 4 | 대부분 수치 기반, 일부 형용사 |
| 3 | 절반 정도 수치 기반 |
| 2 | 형용사 다수, 일부 수치 |
| 1 | 대부분 형용사 |
| 0 | 구체적 수치 없음 |

**금지 표현 → 대체 표현**:

| 금지 | 대체 |
|------|------|
| 매우 높은 정확도 | 74.1% 정확도 |
| 상당한 향상 | +15.3%p 향상 |
| 크게 개선됨 | 2.3배 개선 |
| 빠르게 수렴 | 5 step 내 수렴 |
| 안정적인 학습 | reward std < 0.1 유지 |

---

### 6. Figure Quality (10점)

**Plot이 결과를 명확하게 보여주며, 학술 논문 수준의 품질을 갖추는가.**

| 점수 | 기준 |
|------|------|
| 10 | 모든 Figure가 논문 수준 품질 + 각 Figure에 4가지 관점 해석 |
| 8 | Figure 품질 양호, 해석이 대부분 충분 |
| 6 | Figure 있으나 일부 해석 부족 |
| 4 | Figure 있으나 품질/해석 모두 부족 |
| 2 | 최소한의 Figure만 있음 |
| 0 | Figure 없음 |

**Figure 품질 체크리스트**:
- [ ] 축 레이블이 명확한가 (단위 포함)
- [ ] 범례가 적절한가
- [ ] 제목이 내용을 설명하는가
- [ ] 서브플롯별 개별 해석이 있는가 (a, b, c, d)
- [ ] 비교 대상이 같은 Figure에 포함되어 있는가

---

### 7. Next Steps Clarity (10점)

**다음 실험이 구체적이고 실행 가능하며, 가설과 연결되어 있는가.**

| 점수 | 기준 |
|------|------|
| 10 | 모든 다음 실험이 가설과 연결 + Config 변경 + 예상 결과 |
| 8 | 대부분 구체적이나 일부 부족 |
| 6 | 다음 실험은 있으나 가설 연결이 약함 |
| 4 | 다음 실험이 있으나 모호함 |
| 2 | "향후 연구가 필요하다" 수준 |
| 0 | 다음 단계 언급 없음 |

**좋은 예**:
```
### E5: Dynamic Filtering on Math QA
- Tests: H3 (ratio-based threshold가 긴 trajectory에서도 효과적이다)
- Config:
  max_invalid_ratio: 0.5  # was: fixed threshold == 0
- Expected: Math QA accuracy가 52.3% → 60%+ 개선
- Priority: High
```

**나쁜 예**:
```
향후 더 많은 실험이 필요하다.
(→ 구체성 없음, 가설 연결 없음)
```

---

## 총점 계산

```
Total = Definition-First(25) + Topic-First(20) + Compare-Contrast(15)
      + Insight(15) + Adjectives(5) + Figure(10) + NextSteps(10)
      = 100

통과 기준: ≥ 80점
```

---

## 수정 가이드

### Critical Issues (즉시 수정 필요)

1. **Definition Missing**: 용어 정의 추가
2. **No Source Citation**: 출처 추가
3. **No Executive Summary**: 비교 테이블 추가
4. **Topic-Last Paragraph**: 문단 구조 재배치

### Warnings (개선 권장)

1. **Shallow Insight**: "왜" 분석 추가
2. **Missing Comparison**: 비교 테이블 추가
3. **No Figures**: plot 생성 및 해석 추가
4. **Vague Next Steps**: 구체적 Config 변경사항 추가

### Minor Issues (선택적 개선)

1. **Excessive Adjectives**: 수치로 대체
2. **Missing Context**: 배경 설명 추가
3. **Verbose Expression**: 문장 간결화
