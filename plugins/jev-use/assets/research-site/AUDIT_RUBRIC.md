# 연구판 자가 점검표

주인의 기준을 줄마다 0·1·2 로 매긴다. **2 = 처음 보는 사람이 설명 없이 해낸다 · 1 = 되긴 하나 걸린다 · 0 = 안 된다.**
점수는 반드시 **스크린샷을 직접 보고** 매긴다(코드를 읽고 매기지 않는다). 1280px 와 400px 둘 다 본다.
결과는 `site/AUDIT.md` 에 남기고, 2가 아닌 줄은 고칠 수 있으면 고친 뒤 다시 찍는다(최대 3바퀴).

| 줄 | 보는 것 | 2점 조건 |
|---|---|---|
| **W1** | 주차 진행 | 한 주 자리를 비운 사람이 주차 카드만 읽고 "무엇을 알아보려 했고 · 무엇을 했고 · 무엇이 나왔나"를 말할 수 있다. 숫자마다 근거 파일이 적혀 있고, 철회된 것이 따로 보인다. |
| **S1** | 통계의 범위 | 블록이 우리가 알고 싶은 질문만 다룬다. 블록마다 한 줄 결론과 상태(확정/미확인/철회/진행)가 있다. 자료가 없으면 지어내지 않고 '자료 없음 + 찾은 경로'가 보인다. |
| **S2** | 통계 → 사례 | 어느 통계에서든 두 번 누르면 실제 사례 화면에 닿는다(대표 사례 또는 '전부 보기'). |
| **D1** | 자료(행렬) | 첫 화면에 빈 열·빈 줄이 없다. 결과 칸의 말이 그 자체로 읽히고(색 없이도), 범례가 표 위에 있으며, 누르면 좁혀지는 타일이 있다. |
| **L1** | 진행 중 실험 | 지금 돌고 있는 실험의 수치·관문·판정이 한눈에 있고, 펼치면 카드·판정·보고서 **원문**이 그대로 보인다. |
| **L2** | 지도 | 의도 → 질문 → 가설/방법 → 실험이 그림으로 이어지고, 지금 어디인지("여기")와 왜 거기인지가 보인다. |
| **L3** | 기록 | 맨 위에 '지금 하는 일'이 있고, 기록은 쉬운 말이 먼저 · 기술적 본문은 접혀 있다. 시각이 실제 최신 기록과 맞다. |
| **V1** | 눈에 보이는 것 | 글자가 잘리거나 지나치게 크지 않고, 대비가 충분하며, 400px 폭에서도 가로 스크롤 없이 읽힌다. |
| **P1** | 파이프라인 판 | 연구 전체가 한 장의 그림으로 보이고, 지금 돌고 있는 걸음이 색으로 바로 눈에 띈다. 되돌아간 갈래와 막힌 걸음도 이유와 함께 보인다. |
| **P2** | 판 → 속 | 상자를 한 번 누르면 그 걸음의 통계·사례가 열리고, 모듈을 한 번 더 누르면 그 모듈이 남긴 원문이 그대로 보인다. |
| **C1** | 첫 화면의 말 | 첫 화면에 파일·모듈 이름, 관문·중단 규칙 기호, 영어 상태어가 하나도 없다(빌드 린트가 막는다). |
| **C2** | 10초 시험 | 첫 화면만 보고 열 셀 동안 “목표 · 지금 하는 일 · 어디까지 왔나” 셋을 말할 수 있다. |
| **R1** | 쌓이는 보고서 | 지난 주차 보고서에 헤더 메뉴나 주차 카드에서 닿고, 그 화면이 '얼린 보고서'임을 스스로 알린다. |

## 매기는 법

1. 배포본이 아니라 로컬(`127.0.0.1`)에서 찍는다 — 배포 전에 고치기 위해서다.
2. 탭마다 1280×2000 과 400×1600 을 찍고, 사례 화면·펼친 실험 카드·얼린 보고서도 한 장씩 찍는다.
3. 줄마다 **한 문장 근거**를 적는다("스크린샷 3에서 첫 열 제목이 잘림" 처럼 본 것만).
4. 고친 뒤 다시 찍어 점수를 갱신한다. 고칠 수 없는 것은 0/1 로 남기고 이유를 적는다 — 점수를 올려 적지 않는다.
5. 마지막 표와 남은 흠을 `site/AUDIT.md` 에 그대로 옮긴다. 다른 사람이 같은 스크린샷으로 다시 매길 것이다.
